# 缓存：为什么第二次打开网页更快

示例场景（数值为示意，用来讲清机制）：
- 浏览器到很远的源站一个来回大约 120 毫秒。
- 请求在就近的缓存节点命中时，大约 5 毫秒就能返回。

机制：
1. 第一次请求时缓存里没有这份内容（MISS），请求继续去源站；内容回来的路上，缓存存一份副本。
2. 之后同样的请求命中缓存（HIT），直接从缓存返回，不再去源站。
3. 每份副本都有存活时间（TTL）。源站在响应头里写 `Cache-Control: max-age=3600`，意思是可以存 3600 秒（一小时）。
4. 副本过期后，下一次请求重新回源，拿到新内容再存一份。

一百个请求里，如果大部分命中缓存，源站只需要处理剩下的少数几个。
